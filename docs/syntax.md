# Синтаксис

Шаблоны пишутся на подмножестве Vue, которое однозначно переводится в язык шаблонизатора. Подмножество определяет адаптер шаблонизатора; в таблице ниже показано, во что переводит его Handlebars, а чем отличаются askama и Jinja — в разделе [Шаблонизаторы](./engines). Всё, что за его пределами, — ошибка сборки с указанием файла, строки и столбца.

Те же ошибки показывает ESLint — правило `vitempl/syntax`, см. [ESLint](./eslint).

## Что поддерживается

| Vue                                   | Handlebars                                                        |
| ------------------------------------- | ----------------------------------------------------------------- |
| `{{ user.name }}`                     | `{{user.name}}`                                                   |
| `v-if="a"`, `v-else-if="b"`, `v-else` | `{{#if a}}…{{else if b}}…{{else}}…{{/if}}`                        |
| `v-if="!a"`                           | `{{#unless a}}…{{/unless}}`                                       |
| `v-for="(item, i) in items"`          | `{{#each items as \|item i\|}}…{{/each}}`                         |
| `:href="item.href"`                   | `href="{{item.href}}"`                                            |
| ``:hx-get="`/list?page=${page}`"``    | `hx-get="/list?page={{page}}"`                                    |
| `:disabled="locked"`                  | `{{#if locked}} disabled{{/if}}`                                  |
| `:class="{ active: isActive }"`       | `class="{{#if isActive}}active{{/if}}"`                           |
| `<AppHeader :links="nav" />`          | `{{#> partials/AppHeader null links=nav}}{{/partials/AppHeader}}` |
| `<slot />`                            | `{{#if @partial-block}}{{> @partial-block}}{{/if}}`               |
| `:key`                                | не выводится                                                      |

Выражения — только пути к данным: `a.b.c`, `a?.b`, `a[0]`. В условиях дополнительно допускается отрицание `!путь`, в props и атрибутах — строки, числа и `true`/`false`.

Компонент вызывается с пустым контекстом (`null`), поэтому видит только переданные ему props — как во Vue. Содержимое слота выполняется внутри компонента, но обращается к данным вызывающего шаблона: генератор добавляет к путям `../`.

В `<script setup>` допускаются только импорты компонентов и типов, объявления типов и `defineProps`. Блок `<style>` попадает в сборку, см. [Стили](./introduction#стили).

## Что не поддерживается

- Выражения с операторами, вызовами функций, тернарным оператором, глобальные объекты (`Math`) и служебные переменные (`$props`).
- `v-on` (`@click`), `v-model`, `v-show`, `v-html`, `v-text`, свои директивы, `:style`, `v-bind="объект"`, вычисляемые имена атрибутов и модификаторы.
- Именованные слоты, слоты с параметрами и запасным содержимым.
- `<style scoped>` и `<style module>`, `<script>` без `setup`, любой код в `<script setup>` кроме перечисленного выше.

Интерактивность добавляется через htmx, а не через обработчики Vue: шаблоны выполняет сервер, в браузере Vue нет.

## Отличия от Vue

Шаблон выполняет шаблонизатор сервера, а типы проверяет TypeScript, поэтому в некоторых местах поведение отличается от Vue (примеры для Handlebars):

- **Условия.** Пустой массив в Handlebars ложен, а в JavaScript истинен. Для проверки на пустоту используйте `v-if="items.length"`.
- **Пустые атрибуты.** Для `null` и `undefined` Vue не выводит атрибут, а Handlebars выводит его с пустым значением.
- **Пробелы.** Пробелы в начале и в конце содержимого элемента удаляются, как при рендере Vue.
